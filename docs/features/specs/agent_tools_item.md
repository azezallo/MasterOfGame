# Специфікація інструментів Агента: Предмети та Об'єкти світу (F014)

## Огляд
Цей документ описує архітектуру, систему зберігання, класифікацію та інструменти Майстра (Function Calling API) для роботи з предметами та інтерактивними об'єктами у світі гри.
Предмети виступають зв'язуючою ланкою між локаціями (де вони знаходяться у полі `present_item_ids` або скринях), персонажами/NPC (інвентар, зброя, ключі) та сюжетом (таємні листи, артефакти, квестові предмети).

---

## 1. Класифікація та Властивості предметів (Item Types & Core Properties)

Кожен предмет в ігровому світі класифікується за однією з 9 категорій, що визначає його основну поведінку, спосіб використання та набір додаткових полів у схемі даних:

### 1.1. Типологія предметів (`category`)
1. **`weapon` (Зброя)**: Мечі, луки, кинджали, палиці. Впливають на бойові розрахунки, мають показники шкоди або типу атаки.
2. **`armor` (Обладунки та Щити)**: Лати, шкіряні куртки, шоломи, щити. Змінюють показник захисту персонажа.
3. **`jewelry` (Коштовиці та Прикраси)**: Перстні, амулети, брошки, діадеми, коштовні камені. Могуть бути виключно цінною здобиччю для торгівлі або носіями потужних магічних чар (без зміни ваги інвентаря).
4. **`consumable` (Витратні матеріали)**: Зілля здоров'я, сухі пайки, сувої заклинань, факели. Зникають або витрачають заряди після застосування.
5. **`key` (Ключі та Відмички)**: Фізичні ключі, магічні печатки, значки або предмети-пазли, що відкривають засуви в системі карти чи скринях (працюють через `unlocks_key_id`).
6. **`container` (Контейнери та Скрині)**: Скрині, мішки, гаманці, тайники в стінах. Можуть містити вкладений список інших предметів (`contained_item_ids`), мати власний замок та пастку.
7. **`document` (Книги, Листи та Сувої)**: Носії текстової інформації (щоденники, карти скарбів, листи з погрозами). Майстер використовує їх для розкриття лору або видачі квестів.
8. **`artifact` (Унікальні та Легендарні артефакти)**: Сюжетні предмети з особливими правилами, які не підлягають звичайному зносу чи знищенню.
9. **`misc` (Сміття, Ресурси, Інше)**: Шкури звірів, руда, звичайні побутові речі, екзотичні сюжетні дрібниці (гілка дерева, зламана кінська підкова).

### 1.2. Фізичні та Економічні атрибути (`physical_properties`)
- **Вага (`weight_kg`)**: Використовується системою для контролю навантаження інвентаря гравця чи місткості контейнерів.
- **Міцність та Знос (`durability`)**: Замість складних числових розрахунків для кожної дії, стан предмета має 4 градації:
  * `intact` (Цілий) — стандартний стан.
  * `worn` (Зношений) — предмет довго використовувався, але працює нормально.
  * `damaged` (Пошкоджений) — зброя наносить менше шкоди, броня гірше захищає; потребує ремонту.
  * `broken` (Зламаний) — предмет неможливо використовувати за призначенням, поки коваль або маг не відновить його.
- **Базова вартість (`base_value_gold`)**: Орієнтовна ціна для торгівлі, яка може динамічно змінюватися Майстром залежно від економіки міста або репутації гравця.

### 1.3. Таємниці, Пізнання та Магічні властивості (Secrets, Identification & Magic Draft)
Для звичайних побутових предметів (яких у грі більшість — звичайні мечі, яблука, одяг), поле **`private_profile` може дорівнювати `null`**. Це заощаджує пам'ять БД і вказує, що предмет повністю прозорий для гравця (відсутні приховані властивості, чари чи таємна назва).
Якщо ж предмет приховує особливі властивості, `private_profile` є об'єктом, що містить:
- **Масив незалежних таємниць (`hidden_secrets`)**:
  * Кожна таємниця (`key_function`, `magical_power`, `lore_history`, `curse`) має власний ID (`secret_id`) та статус розпізнавання (`discovery_status: "hidden" | "discovered"`).
  * Гравець може випадково дізнатися, що перстень відкриває таємний люк у каналізацію, навіть не підозрюючи про його магічні властивості (або навпаки).
  * Майстер розкриває кожну таємницю окремо через тул-кол, переключаючи статус конкретного запису в масиві на `discovered`.
- **Загальний статус пізнання (`identification_status`)**:
  * Позначає загальний рівень знань персонажа про предмет (`unidentified` | `partially_identified` | `identified`).
- **Магічні чари та Заряди (`magical_properties_draft`) [ЧЕРНЕТКА]**:
  * Цей блок позначається як чорновий і буде повністю перероблений та синхронізований під час проектування Глобальної магічної системи.
  * На поточному етапі він містить прапорець прив'язки (`attunement_status`) та масив активних чар із зарядами (`active_enchantments`), витрату яких Майстер контролює програмно.

## 2. Спеціальні механіки: Ключі, Контейнери та Документи (Keys, Containers & Documents)

Для безшовної інтеграції предметів із просторовою картою, секретами та наративним лором, система підтримує три спеціалізовані механіки:

### 2.1. Система ключів (`key_id`)
Предмети категорії `key` (або будь-які предмети, що мають таємницю типу `key_function`) слугують фізичними чи магічними ключами до засувів:
- **Принцип роботи**: Поле `special_mechanics.key_properties.unlocks_key_id` містить унікальний строковий ідентифікатор (наприклад: `"key_bronze_gate_01"`).
- **Синхронізація з картою та скринями**:
  * Коли персонаж намагається відкрити зачинений прохід (`transitions.access_status == "locked"`), Майстер програмно перевіряє, чи збігається `transitions.lock_details.key_id` з `unlocks_key_id` будь-якого предмета в інвентарі гравця.
  * Якщо ключ присутній, прохід розблоковується автоматично без необхідності проходження перевірок на злам (`lockpick_dc`).

### 2.2. Контейнери та Скрині (`container`)
Предмети категорії `container` репрезентують мобільні або стаціонарні сховища (скрині, мішки, шафи, трупи, сейфи, приховані тайники):
- **Вкладений інвентар (`contained_item_ids`)**: Масив ідентифікаторів предметів, які знаходяться всередині цього контейнера.
- **Місткість (`capacity_weight_kg`)**: Максимальна сумарна вага предметів, яку можна покласти в контейнер (для сумок чи мішків).
- **Замки та Пастки (`lock_details`, `trap_details`)**:
  * Контейнер може бути зачиненим (`is_locked: true`), вимагаючи відповідного ключа (`key_id`) або успішного зламу відмичками (`lockpick_dc`).
  * Таємна пастка (`has_trap: true`) спрацьовує при невідкритому чи силовому зламі. ШІ-Майстер бачить деталі пастки (`trap_description`, `trap_dc`, `trap_damage`) і запускає відповідний наративний наслідок у чаті.

### 2.3. Книги, Листи та Документи (`document`)
Предмети категорії `document` призначені для передачі лору, підказок до загадок або магічних заклинань:
- **Зміст (`text_content`)**: Текст листа, сторінки щоденника чи стародавнього сувою.
- **Мова та Шифрування (`language`, `is_encrypted`, `decryption_dc`)**:
  * Якщо документ написано невідомою мовою або зашифровано, гравець не може прочитати зміст напряму.
  * Майстер запитує перевірку інтелекту, навички розшифровки або магічне читання мов. Після успіху Майстер зачитує текст у чаті, або видає переклад у UI-досьє документа.

## 3. Шаблони та Динамічна генерація (Templates & Procedural Generation)

Для забезпечення оптимальної роботи з базою даних, швидкої генерації здобичі та уникнення дублювання інформації використовується архітектура шаблонів (Template Inheritance):

### 3.1. Спадкування від шаблонів (`template_id`)
У статичній таблиці БД (`item_templates`) зберігаються базові зразки предметів (наприклад: `tpl_iron_sword`, `tpl_apple`, `tpl_leather_boots`, `tpl_signet_ring`):
- **Економія пам'яті**: Шаблон визначає стандартні значення `category`, `public_profile.name`, `appearance`, базову вагу та стандартну ціну.
- **Принцип перевизначення (Overrides)**: Конкретний екземпляр предмета у світі (`item_id`) посилається на `template_id`. Будь-яке поле, явно вказане в екземплярі, перекриває значення шаблону. Якщо поле відсутнє в екземплярі, бекенд автоматично підставляє значення з `template_id`.
- **Мінімалістичний запис**: Для 90% звичайних предметів у грі запис у базі даних сесії складається лише з кількох рядків:
  ```json
  {
    "item_id": "item_sword_88",
    "template_id": "tpl_iron_sword",
    "private_profile": null,
    "physical_properties": { "durability": { "current": 75, "state": "worn" } },
    "location_context": { "current_owner_type": "location", "current_owner_id": "loc_armory" }
  }
  ```

### 3.2. Процедурна генерація луту "на льоту"
Коли гравці обшукують труп ворога, зачинену шафу чи таємну кімнату, ШІ-Майстер має повну свободу в процедурному створенні предметів:
- **Генерація за шаблоном**: Майстер викликає тул `create_item(template_id, location_context, overrides?)`, вказуючи, де з'явиться предмет (у кімнаті чи всередині скрині).
- **Створення унікальних артефактів**: Для сюжетних знахідок Майстер може передати повний об'єкт із прихованими таємницями (`hidden_secrets`), унікальною назвою та магією, або створити предмет без шаблону (`template_id: null`).

## 4. Інструменти Майстра (Function Calling API — Draft)

Для повноцінного управління предметами, обшуку, модифікації (накладення магії, створення ключів), розкриття таємниць та роботи зі скринями, Майстер використовує наступні 7 інструментів:

### 4.1. Отримання та Пошук (Retrieval & Search)
- **`get_item_context(item_ids: string[])`**
  * *Призначення*: Отримання повних об'єктів для вказаного масиву ідентифікаторів предметів. Майстер отримує як `public_profile`, так і `private_profile` (включаючи всі приховані таємниці, пастки в скринях та справжню магію).
- **`search_items(query?: string, owner_type?: "location" | "npc" | "player" | "container", owner_id?: string, category?: string)`**
  * *Призначення*: Пошук предметів у світі або в інвентарях за фільтрами. Наприклад: знайти всі предмети категорії `key` в поточній кімнаті або весь вміст скрині `item_chest_01`.

### 4.2. Генерація та Модифікація (Creation & Modification)
- **`create_item(template_id: string | null, location_context: object, overrides?: object)`**
  * *Призначення*: Динамічне створення предмета "на льоту" (при обшуку трупів, тайників чи нагородженні квесту). Може використовувати базовий шаблон з перекриттям властивостей (Overrides) або створюватися унікально.
- **`update_item_properties(item_id: string, modifications: object)`**
  * *Призначення*: Універсальний інструмент глибокого редагування будь-яких властивостей існуючого предмета:
    1. **Зміна зносу та власника**: Зміна стану `durability` чи переміщення іншому власнику (`location_context`).
    2. **Магічна модифікація та Заряди**: Додавання або зміна чар і зарядів у `magical_properties_draft` (наприклад: гравець замовив зачарування улюбленого звичайного меча, перетворюючи його `private_profile` з `null` на магічний об'єкт).
    3. **Спеціальні механіки**: Додавання або зміна засувів/ключів у `special_mechanics.key_properties` (наприклад: персонаж провів ритуал, який зробив його меч ключем до магічного порталу або власного логова).

### 4.3. Розкриття таємниць та Інтерактивні механіки (Secrets & Interactions)
- **`reveal_item_secret(item_id: string, secret_id?: string, reveal_all?: boolean)`**
  * *Призначення*: Розкриття таємниць предмета для гравця. Може відкривати точкову таємницю з масиву `hidden_secrets` (переводячи її `discovery_status` у `"discovered"`) або повністю розпізнавати предмет (`identification_status: "identified"`).
- **`unlock_container(container_id: string, key_id?: string, force_open?: boolean)`**
  * *Призначення*: Взаємодія зі скринями, сейфами та контейнерами. Перевіряє наявність ключа чи успіх зламу відмичками, а також автоматично активує таємну пастку (`trap_details`), якщо її не було заздалегідь знешкоджено.
- **`read_document(document_id: string, language?: string, decryption_skill?: number)`**
  * *Призначення*: Читання книг, листів, стародавніх рун і записів. Перевіряє володіння мовою та успіх розшифрування (`decryption_dc`), після чого Майстер наративно зачитує текст у чаті.

## 5. Відображення на UI (Frontend Representation — Player UI Only)

Оскільки інтерфейс призначений виключно для гравця (Майстром є автономний ШІ), відображення предметів у панелі карти чи інвентарі підпорядковується суворим правилам безпеки даних та візуального комфорту:

### 5.1. Ліва бічна панель: Список речей за категоріями (Left Sidebar Items List)
У лівій бічній панелі (інвентар персонажа або список речей, присутніх у кімнаті) всі предмети згруповані за категоріями (`Зброя`, `Обладунки`, `Коштовиці`, `Витратні`, `Ключі`, `Контейнери`, `Документи`, `Артефакти`, `Інше`):
- **Відображення у вигляді кнопок**: Кожен предмет у списку виводиться як інтерактивна кнопка з назвою з `public_profile.name` (або `true_name`, якщо предмет уже впізнано).
- **Колір кнопки як індикатор зносу (`durability`)**:
  * Оскільки в грі зафіксовано 4 усталені стани міцності, колір рамки чи фону кнопки миттєво сигналізує гравцеві про стан речі без зайвих цифр:
    * 🟢 **`intact` (Цілий)** — стандартний спокійний / зелений акцент.
    * 🟡 **`worn` (Зношений)** — жовтий / нейтральний акцент.
    * 🟠 **`damaged` (Пошкоджений)** — помаранчевий / попереджувальний колір, що закликає відремонтувати річ.
    * 🔴 **`broken` (Зламаний)** — червоний / неактивний стан, предмет потребує серйозного відновлення.

### 5.2. Модальне вікно досьє предмета (Item Dossier Popup)
- При натисканні на кнопку предмета відкривається попап (модальне вікно) з детальною інформацією:
  * **Опис та Вигляд**: Поля `appearance` та `public_description`.
  * **Характеристики**: Вага (`weight_kg`), вартість (`base_value_gold`) та точний стан міцності.
  * **Розкриті таємниці та Магія**: Якщо Майстер розкрив певні записи з масиву `hidden_secrets` або предмет має `identification_status: "identified"`, у попапі виводиться окремий блок із магічними ефектами, зарядами чи сюжетною історією.

### 5.3. Сувора ізоляція даних від DevTools (Data Isolation)
Для запобігання підгляданню через інструменти розробника в браузері (DevTools), бекенд виконує жорстку фільтрацію перед відправкою JSON на клієнт:
- Поле `private_profile` повністю видаляється з об'єкта, якщо `identification_status == "unidentified"` та жодна таємниця не розкрита.
- З масиву `hidden_secrets` на клієнт потрапляють виключно ті записи, де `discovery_status == "discovered"`.
- Пастки скринь (`trap_details`) та справжня вартість непізнаних артефактів ніколи не передаються в публічному API інвентаря чи мапи.

## 6. Схеми даних
Для детальної структури даних та JSON-схеми предмета дивіться файл: `docs/features/specs/item_data_schema.md`.
