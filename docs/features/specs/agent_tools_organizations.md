# Специфікація інструментів Агента: Організації (F011)

> [!IMPORTANT]
> Цей документ є технічною специфікацією для всієї фічі (як бекенд-логіки, так і UI). Він описує систему фракцій та організацій, яка дозволяє ШІ-Майстру робити світ живим та соціально мотивованим, а також принципи їх взаємодії з гравцем.

## 1. Загальний опис та призначення фічі

**Організації (фракції, гільдії, ордени, секти тощо)** — це ключовий соціальний шар світу гри. Вони існують для того, щоб надати неігровим персонажам (NPC) глобальні цілі, мотивацію та правила поведінки, а гравцю — можливість соціальної прогресії.

**Навіщо потрібна ця фіча:**
1. **Мотивація NPC**: Без організацій кожен NPC діяв би лише у власних інтересах. Завдяки цій системі ШІ-Майстер розуміє контекст поведінки персонажів (наприклад, стражник не візьме хабар через фанатичну відданість ордену, або торговець зробить знижку члену своєї гільдії).
2. **Глобальні інтереси**: Організації мають власні цілі (як відкриті, так і таємні), ресурси та ієрархію. Це дозволяє створювати політичні інтриги та масштабні конфлікти. Крім того, самі організації можуть бути як публічними (як міська варта), так і абсолютно таємними (секретні культи, про існування яких знають одиниці).
3. **Прогресія гравця**: Гравець може заробляти довіру, отримувати ранги, приєднуватись до фракцій або ставати їхнім ворогом, що напряму впливатиме на те, як світ (і Майстер) реагує на його дії.

У концепції **Sovereign AI**, ШІ-Майстер не керується жорсткими скриптами, а читає цілі та поточний стан організацій через інструменти (API). На основі цих даних Майстер логічно і наративно обґрунтовано формує реакцію світу на будь-які дії гравця.

## 2. Схема даних (Data Schema)

Дані про організації та приналежність до них зберігаються у форматі JSON. Схема базується на принципах вільної архітектури, щоб дати Майстру максимальну гнучкість для створення наративу та відіграшу.

### 2.1. Структура Організації (Organization)

```json
{
  "id": "org_thieves_guild",
  "name": "Гільдія Тіней",
  "type": "syndicate",
  "is_secret": true,
  "is_known_to_player": false,
  "description": "Мережа злодіїв та контрабандистів, що контролює тіньовий ринок столиці.",
  
  // Бекенд зберігає ієрархію як посилання на керівника (superior_id).
  // Перед передачею контексту Майстру, бекенд динамічно генерує з цього Mermaid-граф (graph TD).
  "hierarchy": [
    { 
      "rank_id": "M",
      "rank_name": "Майстер Тіней", 
      "superior_id": null,
      "privileges": ["Керування осередком"],
      "duties": ["Забезпечення безпеки осередку", "Розподіл фінансів"]
    },
    { 
      "rank_id": "S1",
      "rank_name": "Тінь", 
      "superior_id": "M",
      "privileges": ["Скупка краденого", "Доступ до замовлень"],
      "duties": ["Виконання мінімум 1 контракту на місяць", "Навчання Шукачів"]
    },
    { 
      "rank_id": "S2",
      "rank_name": "Шпигун", 
      "superior_id": "M",
      "privileges": ["Збір інформації", "Недоторканність"],
      "duties": ["Збір інформації про патрулі міської варти"]
    },
    { 
      "rank_id": "N",
      "rank_name": "Шукач", 
      "superior_id": "S1",
      "privileges": ["Доступ до базового притулку"],
      "duties": ["Віддавати 10% здобичі гільдії", "Виконувати дрібні доручення"]
    }
  ],
  
  "objectives": {
    "public": ["Взаємодопомога", "Захист бідних районів"],
    "secret": ["Повалення поточного намісника", "Монополізація ринку забороненої магії"]
  },
  
  "resources": {
    "wealth_level": "high",
    "manpower_level": "medium",
    "influence": "high"
  }
}
```

### 2.2. Приналежність персонажа (Affiliation)
Цей масив об'єктів зберігається у профілі гравця або NPC (див. [npc_data_schema.md](file:///d:/My/MasterOfGame/docs/features/specs/npc_data_schema.md)), вказуючи на їхні зв'язки з різними організаціями.

```json
{
  "organization_id": "org_thieves_guild",
  "rank_id": "N",
  "reputation": 25,
  "interactions": [
    {
      "timestamp": "2026-07-28T10:00:00Z",
      "description": "Допоміг знайти зрадника у південному осередку.",
      "reputation_change": 15
    },
    {
      "timestamp": "2026-07-25T14:20:00Z",
      "description": "Випадково зірвав поставку контрабанди під час сутички з вартою.",
      "reputation_change": -5
    }
  ]
}
```
- **rank_id**: ID рангу з ієрархії організації. Якщо значення `null` — персонаж не є членом цієї організації (або був вигнаний).
- **reputation**: (число від -100 до 100). Визначає, чи є персонаж ворогом (негативне значення), чи другом (позитивне). Навіть без офіційного членства (`rank_id`: null) персонаж може мати репутацію у фракції.
- **interactions**: Масив визначних подій, де персонаж (або гравець) суттєво вплинув на організацію. Це дає ШІ-Майстру живий контекст, чому репутація знаходиться на певному рівні, і дозволяє генерувати осмислені діалоги (наприклад, нагадати гравцеві про його старі гріхи або заслуги перед фракцією).

## 3. Інструменти читання (API Контракти)

Ці інструменти (Function Calling) дозволяють ШІ-Майстру отримувати інформацію про фракції для формування наративу та відповідей. Важливо, що вони розроблені для оптимізації контексту (не завантажувати всю базу, а лише необхідні дані).

### 3.1. `get_organizations_list`
- **Опис**: Отримує загальний список організацій, щоб Майстер міг дізнатися про існуючі фракції у світі (пошук за фільтрами).
- **Параметри**:
  - `filter` (Об'єкт, опціонально): 
    - `type` (String) — фільтр за типом організації (наприклад, `syndicate`, `military`, `guild`).
    - `is_secret` (Boolean) — пошук відкритих або таємних фракцій.
- **Результат**: Масив стислих об'єктів організацій, кожен з яких містить `id`, `name`, `type`, `is_secret` та `description`. Дозволяє Майстру знайти потрібну фракцію для подальшого глибокого дослідження.

### 3.2. `get_organization_details`
- **Опис**: Отримує загальну інформацію про структуру фракції, її ієрархію та ресурси.
- **Параметри**:
  - `organization_id` (String, обов'язково): Унікальний ідентифікатор фракції.
- **Результат**: Повертає базові дані (`name`, `description`, `is_secret`, `resources`) та розгорнуту ієрархію. Зверніть увагу: бекенд автоматично конвертує базу даних ролей (`superior_id`) у готовий `mermaid_graph` перед відправкою, щоб Майстер відразу візуально розумів дерево підпорядкування, а також повертає масив ролей з їхніми обов'язками (`duties`) та привілеями (`privileges`).

### 3.3. `get_organization_objectives`
- **Опис**: Отримує поточні цілі організації. Відокремлено від `get_organization_details` для економії токенів, якщо Майстру потрібна лише структура, а не мотивація фракції.
- **Параметри**:
  - `organization_id` (String, обов'язково).
- **Результат**: Масив `public` (відкриті) та `secret` (таємні) цілей. Майстер використовує цю інформацію, щоб формувати довгострокові плани NPC, видавати гравцеві місії або генерувати конфлікти між різними угрупованнями.

### 3.4. `get_organization_members`
- **Опис**: Пошук NPC, що належать до певної організації. 
- **Параметри**:
  - `organization_id` (String, обов'язково).
  - `filter` (Об'єкт, опціонально):
    - `rank_id` (String) — знайти конкретний ранг (наприклад, усіх лідерів або всіх новобранців).
    - `location_id` (String) — знайти членів фракції у певній локації.
- **Результат**: Масив коротких профілів NPC (лише `npc_id`, `name`, `rank_id`, `current_location_id`). Цей інструмент ідеально підходить, якщо гравець заявляє: "Я хочу знайти місцевого представника Гільдії Тіней", і Майстру потрібно швидко зрозуміти, хто з існуючих NPC у поточній локації відповідає цьому запиту.

## 4. Інструменти оновлення (API Контракти)

ШІ-Майстер може змінювати стан фракцій та приналежність гравця залежно від подій у світі (наприклад, результат квестів, дій гравця або глобальних подій).

### 4.1. `update_player_organization_affiliation`
- **Опис**: Змінює поточний зв'язок гравця з фракцією.
- **Параметри**:
  - `organization_id` (String, обов'язково).
  - `updates` (Об'єкт, обов'язково):
    - `rank_id` (String | null) — призначити гравця на нову посаду (або зняти з неї, передавши `null`).
    - `reputation_delta` (Integer) — на скільки змінити репутацію гравця (наприклад, -10 або +15).
    - `interaction_event` (Об'єкт) — запис про визначну подію. Містить `description` (наративний опис того, що зробив гравець) та `reputation_change`. Цей об'єкт буде додано до масиву `interactions` гравця для збереження контексту на майбутнє.
- **Результат**: Бекенд знаходить об'єкт приналежності у профілі гравця (або створює новий, якщо його не було), застосовує `reputation_delta`, змінює `rank_id` та зберігає історію.

### 4.2. `update_organization_status`
- **Опис**: Змінює глобальні параметри самої організації (використовується, якщо Майстер вирішує, що масштабні дії гравця або плин часу суттєво вплинули на фракцію в цілому).
- **Параметри**:
  - `organization_id` (String, обов'язково).
  - `updates` (Об'єкт, обов'язково):
    - `is_known_to_player` (Boolean) — дозволяє Майстру офіційно "розкрити" існування організації для гравця, після чого вона з'явиться в UI.
    - `objectives_override` (Об'єкт) — дозволяє Майстру повністю замінити `public` або `secret` цілі фракції (наприклад, після зміни лідера).
    - `resources_change` (Об'єкт) — зміна ресурсів (`wealth_level`, `manpower_level`, `influence`). Майстер може передати нові значення (наприклад, `wealth_level: "low"`), якщо, наприклад, скарбницю гільдії було обікрадено.
- **Результат**: Оновлення центрального об'єкта фракції у світі гри.

### 4.3. `create_organization`
- **Опис**: Динамічне створення нової організації під час гри. Використовується, коли Майстер генерує нове угруповання на льоту (наприклад, новий культ, союз або банда, що з'явилася в результаті дій гравця).
- **Параметри**:
  - `name` (String, обов'язково) — назва організації.
  - `type` (String, обов'язково) — тип (наприклад, `cult`, `syndicate`, `military`).
  - `is_secret` (Boolean, обов'язково) — чи є організація таємною.
  - `description` (String, обов'язково) — короткий опис для Майстра.
  - `objectives` (Об'єкт, опціонально) — стартові `public` та `secret` цілі.
  - `hierarchy` (Масив, опціонально) — стартова ієрархія ролей (або порожня для подальшого наповнення).
- **Результат**: Створює новий об'єкт `Organization` у базі даних та повертає його згенерований `organization_id`. Майстер може одразу використовувати цей ID для додавання членів через `update_npc_organization_affiliation`.

## 5. Спосіб відображення на UI (Frontend Representation & UI Components)

Для підтримання імерсивності та зручного доступу гравця до соціального контексту світу, відображення організацій базується на наступних принципах (схожих до системи NPC, але орієнтованих на фракції):

### 5.1. Базові UX-принципи та Ізоляція даних
- **Безпека даних (Data Isolation)**: Як і з NPC, бекенд відфільтровує `secret` цілі та внутрішні ресурси, про які гравець не має знати. Відображення організації на UI суворо керується полем `is_known_to_player`. Навіть якщо гравець має об'єкт `Affiliation` (наприклад, не знаючи, на кого працює), організація не з'явиться в UI, доки Майстер наративно не розкриє її та не оновить статус через `update_organization_status({ is_known_to_player: true })`.
- **Відсутність мета-геймінгу**: Репутація може відображатися як число (або у вигляді статус-бару від ворожнечі до пошани), але зміна репутації відбувається наративно (через текст Майстра), без спливаючих вікон типу "+15 Reputation".

### 5.2. Конкретні UI-компоненти (Player UI Layout)
- **Права бічна панель (Right Aside Panel — "Фракції та Зв'язки")**:
  - Відображається як окрема вкладка поруч із вкладкою NPC ("Активне оточення") у правому соціальному сайдбарі.
  - Відображає список із **3-5 найбільш актуальних організацій** (тих, з якими гравець взаємодіяв останнім часом, або де має найвищий/найнижчий ранг).
  - Компактний елемент списку показує: **Назву фракції**, **Поточний ранг гравця** (якщо є) та індикатор **Репутації** (наприклад, кольорову крапку або короткий статус "Ворог/Союзник").
  - При кліку на елемент викликається Попап досьє організації.
  
- **Кнопка та Попап "Довідник Фракцій" (Factions Directory Modal)**:
  - Кнопка в шапці бічної панелі відкриває глобальний довідник.
  - Тут виводяться всі відомі гравцеві організації.
  - Є можливість фільтрації (наприклад: `Дружні`, `Ворожі`, `Моя гільдія`).

- **Попап досьє організації (Faction Dossier Modal)**:
  - Відображає детальну відому інформацію: опис, відкриті цілі (`public objectives`).
  - **Ієрархія (Візуалізація)**: Відображає схему ієрархії (якщо вона відома гравцю) і чітко підсвічує поточне місце гравця (`rank_id`) в цій структурі.
  - **Історія взаємодій (Interactions History)**: Виводить список з масиву `interactions` (опис подій, що вплинули на репутацію), працюючи як журнал пам'яті відносин з цією фракцією.
  - **Нотатки**: Як і в NPC, гравець може вести власні текстові записи про фракцію.

- **Адаптивність (Mobile / Responsive UX)**:
  - На мобільних пристроях список фракцій ховається у спільне гамбургер-меню (або таб-бар "Соціум"). Попапи відкриваються на весь екран.

## 6. Сценарії взаємодії (Narrative Flows)

Щоб продемонструвати, як ШІ-Майстер інтегрує ці інструменти в ігровий процес без розриву імерсивності, нижче наведено кілька типових ситуацій:

### Сценарій 1: Вступ до фракції
1. **Гравець**: *"Я приношу вкрадений амулет Майстру Тіней і прошу прийняти мене до Гільдії."*
2. **ШІ-Майстер** (аналізує стейт та контекст): Перевіряє інвентар гравця, чи є там амулет. Бачить, що умова виконана.
3. **Виклик інструменту**: Майстер викликає `update_player_organization_affiliation`:
   - `organization_id`: "org_thieves_guild"
   - `updates`: `{ rank_id: "N", reputation_delta: 10, interaction_event: { description: "Приніс вкрадений амулет і довів свою корисність.", reputation_change: 10 } }`
4. **Наративна відповідь**: *"Майстер Тіней бере амулет, його очі задоволено блищать у темряві. 'Ти довів свою спритність. Відтепер ти — Шукач'. Тобі видають ключ від базового притулку."*
5. **UI**: У бічній панелі гравця з'являється "Гільдія Тіней" із рангом "Шукач" та позитивною репутацією.

### Сценарій 2: Розкриття таємної організації
1. **Гравець**: *"Я ретельно оглядаю вівтар у підвалі покинутого будинку."*
2. **ШІ-Майстер**: Завдяки даним локації бачить, що це вівтар "Культу Чорного Сонця" (`is_secret: true`, `is_known_to_player: false`).
3. **Виклик інструменту**: Майстер вирішує, що гравець знайшов достатньо доказів, і викликає `update_organization_status`:
   - `organization_id`: "org_black_sun"
   - `updates`: `{ is_known_to_player: true }`
