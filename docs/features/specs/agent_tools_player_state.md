# F009: Інструменти ШІ-Майстра — Стан та Показники Гравця

## 1. Загальний опис та концепція (Narrative-First)

Згідно з принципами **Narrative-First UI** та **Sovereign AI Master**, інтерфейс гравця виступає виключно як дзеркало ігрового світу та поточного стану персонажа. 

Гравець не має механічних кнопок прямої дії (на кшталт *"Кастувати магію вогню"* або *"Полікувати поранення"*). Замість цього гравець описує свої дії у довільній текстовій формі (наприклад, *"Я намагаюся зосередитися і випустити вогняну стрілу у мішень"*). 

ШІ-Майстер:
1. Оцінює намір гравця, фізичний та психологічний стан, показники навичок та наявність ресурсів.
2. Приймає рішення про успіх, частковий успіх або невдачу дії.
3. Генерує художню текстову відповідь для гравця.
4. Одночасно викликає інструменти системи (`update_player_state`) для оновлення числових показників, навичок та якісних ефектів у БД.

---

## 2. Модель даних стану гравця

Стан гравця зберігається у виглядi структурованого об'єкта `PlayerStateProfile`, який складається з якісних станів (які мають часові позначки), базових атрибутів, похідних характеристик, параметрів магії та динамічного списку навичок.

> [!IMPORTANT]
> **Структура Навичок (`SkillEntry[]`):**
> Для дотримання принципів Narrative-First UI навички зберігаються не як ключ-значення (`{"spear_mastery": 50}`), а як масив об'єктів із природною назвою та рівнем: `[{ "name": "Володіння пікою", "value": 50 }]`. Це дає змогу ШІ-Майстру вільно створювати нові навички природною мовою без жорсткої прив'язки до статичних ключів перекладу.

### 2.1. Структура JSON

```json
{
  "physical_states": [
    {
      "name": "light_wound",
      "timestamp": "1024-06-15T14:00:00.000Z"
    }
  ],
  
  "body_states": [
    {
      "name": "fatigue",
      "timestamp": "1024-06-15T13:15:00.000Z"
    }
  ],
  
  "psychological_states": [
    {
      "name": "stress",
      "timestamp": "1024-06-15T13:40:00.000Z"
    }
  ],
  
  "attributes": {
    "strength": 25,
    "agility": 30,
    "endurance": 28,
    "perception": 22,
    "willpower": 20
  },
  
  "derived_stats": {
    "max_carry_weight_kg": 55.0
  },
  
  "magic_stats": {
    "mana_pool": 100,
    "current_mana": 25,
    "mana_flow": 5,
    "base_regen": 10.0
  },
  
  "skills": [
    { "name": "Магія вогню", "value": 50 },
    { "name": "Фехтування мечем", "value": 30 },
    { "name": "Приховане пересування", "value": 15 }
  ]
}
```

> [!NOTE]
> **Таймкоди станів**: Кожен якісний стан містить поле `timestamp` (час у форматі ISO 8601 у часовому вимірі ігрового світу), яке вказує, коли саме гравець отримав цей стан. Це необхідно для того, щоб ШІ-Майстер міг оцінювати тривалість ефектів (наприклад, скільки ігрового часу гравець кровоточить чи голодує) і розумно знімати їх, послаблювати або нарощувати наслідки.

### 2.2. Мапінг числових значений в описові

**Базові атрибути (Attributes: 1-100):**
- **Сила (strength)**: Впливає на `max_carry_weight_kg` (формула: `5.0 + strength * 2.0`), фізичну шкоду та здатність виконувати дії, що потребують фізичної міці.
- **Спритність (agility)**: Визначає швидкість реакції, ухилення, координацію та точність рухів.
- **Витривалість (endurance)**: Здатність довгостроково переносити навантаження, опір до втоми (`fatigue`) та фізичних виснажень.
- **Сприйняття (perception)**: Уважність до деталей, здатність помічати пастки, приховані двері або відчувати засідку.
- **Сила волі (willpower)**: Психологічна стійкість, опір паніці, стресу та магічному впливу на розум.

**Навички (Skills: 1-100):**
- `0 - 19`: **Початківець**
- `20 - 39`: **Учень**
- `40 - 59`: **Практик**
- `60 - 79`: **Майстер**
- `80 - 100`: **Грандмайстер**

**Запас мани (Current Mana % від Mana Pool):**
- `80% - 100%`: Повний резерв (Енергія б'є через край).
- `40% - 79%`: Часткова витрата (Нормальний робочий стан).
- `15% - 39%`: Виснаження (Відчутна втома від магії, важко концентруватися).
- `0% - 14%`: Критичне виснаження (Магічний резерв порожній, спроби касту можуть призвести до фізичної шкоди або шоку).

## 3. Специфікація інструментів

### 3.1. `get_player_state`
**Опис**: Отримує поточний стан гравця для прийняття рішень щодо можливості виконання дій.
- **Вхідні параметри**: Немає.
- **Вихідні дані**: Повертає об'єкт JSON зі структурою `PlayerStateProfile`.

### 3.2. `update_player_state`
**Опис**: Змінює стан гравця на основі наративних наслідків дій (поранення, витрата мани, оновлення характеристик, прокачка навичок).
- **Вхідні параметри (всі необов'язкові)**:
  - `add_physical_states` (array of strings): Додає нові фізичні стани (напр. `["heavy_wound"]`).
  - `remove_physical_states` (array of strings): Видаляє фізичні стани за їхньою назвою.
  - `add_body_states` (array of strings): Додає тілесні стани (напр. `["fatigue"]`).
  - `remove_body_states` (array of strings): Видаляє тілесні стани.
  - `add_psychological_states` (array of strings): Додає психологічні стани (напр. `["shock"]`).
  - `remove_psychological_states` (array of strings): Видаляє психологічні стани.
  - `mana_delta` (integer): Зміна поточного значення `current_mana` (+30 або -15).
  - `mana_percent` (number): Відсоткова зміна мани (-50 для зняття 50%).
  - `update_attributes` (object): Об'єкт для оновлення базових атрибутів (напр. `{"strength": 30}`).
  - `update_skills` (array of objects): Масив об'єктів для додавання або оновлення навичок (напр. `[{"name": "Володіння пікою", "value": 50}]`).
  - `skill_name` (string): Назва окремої навички для зміни чи додавання (напр. `"Володіння пікою"`).
  - `skill_value` (integer): Абсолютне значення навички (від 0 до 100).
  - `skill_delta` (integer): Одноразовий приріст або зниження рівню навички (напр. `+10`).
  - `update_magic_stats` (object): Об'єкт оновлення максимального пулу мани, потоку та швидкості відновлення (`mana_pool`, `mana_flow`, `base_regen`).
- **Вихідні дані**: Повертає оновлений об'єкт стану гравця (бек-енд автоматично перераховує `max_carry_weight_kg`).

## 4. Приклади системної взаємодії (API та UI)

### 4.1. Каст заклинання та витрата ресурсів
1. **Дія гравця (UI)**: *"Збираю ману і випалюю замок на дверях вузьким струменем вогню"*.
2. **Читання стану (API)**: Перед відповіддю ШІ-Майстер отримує поточний стан гравця через `get_player_state`.
3. **Логіка ШІ**: Майстер вирішує, що дія вдала, і списує 15 одиниць мани.
4. **Запис стану (API)**: ШІ-Майстер викликає тул `update_player_state`:
   ```json
   {
     "mana_delta": -15,
     "skill_name": "Магія вогню",
     "skill_delta": 1
   }
   ```
5. **Відображення на UI**: Панель гравця миттєво оновлює рівень мани та відображає прогрес навички *"Магія вогню"*.
