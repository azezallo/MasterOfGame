# Специфікація інструментів Агента: Стан гравця (F009)

> [!IMPORTANT]
> Цей документ є технічною специфікацією для розробки бекенду (API контрактів) та фронтенду (UI). Він **не є промптом** для ШІ-Майстра, а описує системну архітектуру та структуру даних, на базі якої розроблятиметься гра.

## 1. Огляд та Концепція

Цей модуль описує інструменти для отримання та оновлення показників персонажа. Він відіграє ключову роль у симуляції **Вільної Магії** та визначенні можливостей гравця.

### 1.1. Гібридна система станів
Відповідно до фундаментальної механіки гри, стан гравця є гібридним:
- **Безчислові (якісні) стани**: Замість класичної "смужки здоров'я" (HP) використовуються описові масиви станів із зазначенням часу їх отримання (таймкодом). Фізичні травми (напр., *крововтрата*, *перелом*), тілесні стани (*виснаження*, *втома*) та психологічні стани (*шок*, *паніка*) безпосередньо впливають на те, які дії гравець здатний виконати фізично, а завдяки таймкодам ШІ-Майстер може розумно знімати або нарощувати ці стани з плином часу.
- **Числові магічні та навичкові параметри**: Для забезпечення глибокої симуляції магії, параметри Запас мани (Mana Pool), Швидкість відновлення мани (Mana Flow) та Рівень навичок (Skill Level) відстежуються **числово**.

### 1.2. Роль ШІ-Майстра (Sovereign AI)
ШІ-Майстер ніколи не показує гравцеві "голі" числа в інтерфейсі (крім випадків системних блоків за запитом). Майстер відповідає за **переклад числових значень у якісний опис**. 
> [!NOTE]
> *(Приклади того, як ШІ-Майстер перекладає числа навичок у наратив, будуть додані та актуалізовані пізніше, після повної деталізації магічної системи).*

---
*(Наступні розділи будуть заповнені на наступних етапах: Схема даних (Етап 2), Інструменти (Етап 3) та Сценарії взаємодії (Етап 4))*

## 2. Схема даних (player_state)

Дані про стан гравця зберігаються у форматі JSON і містять дві основні категорії: **якісні масиви станів** та **числові магічні/навичкові параметри**.

### 2.1. Структура JSON

```json
{
  "physical_states": [
    { "name": "light_wound", "timestamp": "2026-07-28T10:00:00Z" },
    { "name": "blood_loss", "timestamp": "2026-07-28T10:05:00Z" }
  ], 
  "body_states": [
    { "name": "fatigue", "timestamp": "2026-07-28T11:30:00Z" },
    { "name": "hunger", "timestamp": "2026-07-28T08:00:00Z" }
  ],
  "psychological_states": [
    { "name": "stress", "timestamp": "2026-07-28T10:05:00Z" }
  ],
  
  "attributes": {
    "strength": 25,
    "agility": 30,
    "endurance": 28,
    "perception": 22,
    "willpower": 20
  },
  
  "derived_stats": {
    "max_carry_weight_kg": 55.0
  },
  
  "magic_stats": {
    "mana_pool": 100,
    "current_mana": 25,
    "mana_flow": 5
  },
  
  "skills": {
    "fire_magic": 50,
    "sword_fighting": 30,
    "stealth": 15
  }
}
```

> [!NOTE]
> **Таймкоди станів**: Кожен якісний стан містить поле `timestamp` (час у форматі ISO 8601), яке вказує, коли саме гравець отримав цей стан. Це необхідно для того, щоб ШІ-Майстер міг оцінювати тривалість ефектів (наприклад, скільки ігрового або реального часу гравець кровоточить чи голодує) і розумно знімати їх, послаблювати або навпаки нарощувати наслідки з плином часу.

### 2.2. Мапінг числових значень в описові
ШІ-Майстер має використовувати ці таблиці для перекладу числових значень у наратив під час прийняття рішень. Значення атрибутів та навичок органічно зростають у процесі їх активного використання у грі.

**Базові атрибути (Attributes: 1-100):**
- **Сила (strength)**: Впливає на `max_carry_weight_kg`, фізичну шкоду та здатність виконувати дії, що потребують фізичної міці.
- **Спритність (agility)**: Визначає швидкість реакції, ухилення, координацію та точність рухів.
- **Витривалість (endurance)**: Здатність довгостроково переносити навантаження, опір до втоми (`fatigue`) та фізичних виснажень.
- **Сприйняття (perception)**: Уважність до деталей, здатність помічати пастки, приховані двері або відчувати засідку.
- **Сила волі (willpower)**: Психологічна стійкість, опір паніці, стресу та магічному впливу на розум.

**Навички (Skills: 1-100):**
> [!NOTE]
> *(Тимчасовий блок: детальний мапінг рівнів навичок буде розроблено та додано після фінальної деталізації магічної системи. Поки що розглядаємо 1-100 як абстрактну прогресію).*

**Запас мани (Current Mana % від Mana Pool):**
- `80% - 100%`: Повний резерв (Енергія б'є через край).
- `40% - 79%`: Часткова витрата (Нормальний робочий стан).
- `15% - 39%`: Виснаження (Відчутна втома від магії, важко концентруватися).
- `0% - 14%`: Критичне виснаження (Магічний резерв порожній, спроби касту можуть призвести до фізичної шкоди або шоку).

## 3. Специфікація інструментів

Нижче наведено специфікацію бекенд-інструментів, які доступні ШІ-Майстру для взаємодії зі станом гравця. Гравець напряму їх не викликає.

### 3.1. `get_player_state`
**Опис**: Отримує поточний стан гравця для прийняття рішень щодо можливості виконання дій.
- **Вхідні параметри**: Немає (тул автоматично бере контекст поточної сесії/гравця).
- **Вихідні дані**: Повертає об'єкт JSON зі структурою, описаною в розділі `2.1. Структура JSON`.

### 3.2. `update_player_state`
**Опис**: Змінює стан гравця на основі наративних наслідків дій (поранення, витрата мани, отримання досвіду тощо).
- **Вхідні параметри (всі необов'язкові)**:
  - `add_physical_states` (array of strings): Додає нові фізичні стани (напр. `["heavy_wound"]`). Бекенд автоматично додасть до них поточний `timestamp`.
  - `remove_physical_states` (array of strings): Видаляє фізичні стани за їхньою назвою (напр. при лікуванні).
  - `add_body_states` (array of strings): Додає тілесні стани (напр. `["fatigue"]`). Бекенд автоматично додасть поточний `timestamp`.
  - `remove_body_states` (array of strings): Видаляє тілесні стани за їхньою назвою.
  - `add_psychological_states` (array of strings): Додає психологічні стани (напр. `["shock"]`). Бекенд автоматично додасть поточний `timestamp`.
  - `remove_psychological_states` (array of strings): Видаляє психологічні стани за їхньою назвою.
  - `mana_delta` (integer): Зміна поточного значення `current_mana`. Може бути негативним (витрата мани на каст) або позитивним (відновлення). Система автоматично не дасть мані впасти нижче 0 або перевищити `mana_pool`.
  - `update_attributes` (object): Об'єкт для оновлення базових атрибутів (сила, витривалість тощо). Наприклад, `{"strength": 26}` для відображення органічного прогресу після виснажливого бою чи тренувань.
  - `update_skills` (object): Об'єкт для оновлення числових значень навичок. Наприклад, `{"fire_magic": 51}` для відображення органічного прогресу.
- **Вихідні дані**: Повертає оновлений об'єкт стану гравця (бек-енд автоматично перераховує `derived_stats`, такі як `max_carry_weight_kg`, якщо змінилася `strength`).

## 4. Приклади системної взаємодії (API та UI)

У цьому розділі наведено приклади того, як саме система (Бекенд, ШІ-Майстер та Фронтенд) взаємодіє зі станом гравця під час гри.

### 4.1. Каст заклинання та витрата ресурсів
1. **Дія гравця (UI)**: Гравець вводить текст у чат: *"Збираю ману і випалюю замок на дверях вузьким струменем вогню"*.
2. **Читання стану (API)**: Перед тим, як згенерувати відповідь, пайплайн ШІ-Майстра отримує поточний стан гравця через `get_player_state`.
   - *Дані*: `current_mana` = 25, `mana_flow` = 5, навичка `fire_magic` = 50.
3. **Логіка ШІ**: Майстер вирішує, що дія можлива, але вимагає багато енергії. Він генерує описову відповідь для гравця та визначає механічні наслідки.
4. **Запис стану (API)**: ШІ-Майстер викликає тул `update_player_state`:
   ```json
   {
     "mana_delta": -20,
     "add_body_states": ["fatigue"]
   }
   ```
5. **Оновлення інтерфейсу (UI)**: Бекенд оновлює базу даних і відправляє оновлений стан на клієнт (наприклад, через WebSocket). UI оновлює відповідні компоненти згідно з правилами відображення стану (див. Розділ 5).

### 4.2. Отримання травми
1. **Дія**: NPC завдає удару гравцю під час бою.
2. **Запис стану (API)**: ШІ-Майстер вирішує, що гравець отримав поранення, і викликає `update_player_state`:
   ```json
   {
     "add_physical_states": ["light_wound", "bleeding"],
     "add_psychological_states": ["stress"]
   }
   ```
3. **Обмеження подальших дій**: У наступних ходах `get_player_state` повертатиме ці стани. Якщо гравець спробує виконати складну магію або акробатичний трюк, ШІ-Майстер, бачачи стан `bleeding` та `stress`, наративно ускладнить або заблокує цю дію.
