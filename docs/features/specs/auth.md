# Специфікація фічі: Авторизація та Реєстрація (Auth)

## Огляд
Ця фіча забезпечує можливість створення облікових записів гравців та безпечний вхід у систему. Використовується окрема база даних `saves/users.db` для зберігання постійних даних гравців та активних сесій.

## Роль гравця
- **Гость**: Бачить попап авторизації при вході на сторінку.
- **Зареєстрований гравець**: Може створювати обліковий запис, входити в систему та отримувати доступ до ігрового контенту за допомогою куки сесії.

## Вимоги до даних (Database Schema - `saves/users.db`)

### Таблиця `players`
| Поле | Тип | Опис |
|-------|-----|-------|
| `login` | TEXT | Унікальний ідентифікатор гравця (Primary Key). |
| `password_hash` | TEXT | Хеш пароля, отриманий за допомогою алгоритму BCrypt або Argon2. |

### Таблиця `sessions`
| Поле | Тип | Опис |
|-------|-----|-------|
| `session_id` | TEXT | Унікальний випадковий токен сесії (Primary Key). |
| `login` | TEXT | Ідентифікатор гравця, що володіє сесією. |
| `expires_at` | INTEGER | Unix timestamp моменту закінчення терміну дії сесії. |

## Вимоги до API (Backend)

### 1. Реєстрація (`POST /auth/register`)
- **Вхідні дані**: `login` (string), `password` (string).
- **Дії**:
    - Перевірити, чи існує вже гравець з таким `login`.
    - Згенерувати хеш пароля.
    - Записати нового гравця в таблицю `players`.
    - Повернути успіх або помилку (наприклад, "Login already taken").
- **Відповідь**: JSON з повідомленням успіху або помилкою.

### 2. Авторизація (`POST /auth/login`)
- **Вхідні дані**: `login` (string), `password` (string).
- **Дії**:
    - Знайти гравця за `login`.
    - Порівняти введений пароль з хешем у БД.
    - Якщо пароль правильний, згенерувати новий `session_id`.
    - Записати запис у таблицу `sessions` з поточним часом + термін дії (наприклад, 24 години).
    - Відправити `session_id` клієнту через HTTP-куку (`Set-Cookie`).
- **Відповідь**: JSON з даними гравця або помилкою.

### 3. Отримання даних гравця (`GET /auth/me`)
- **Механізм**: Витягувати `session_id` з куки.
- **Дії**:
    - Перевірити існування сесії в таблиці `sessions`.
    - Перевірити, чи не закінчився термін дії (`expires_at`).
    - Якщо все добре, повернути дані гравця.
- **Відповідь**: JSON з даними гравця або 401 Unauthorized.

## Вимоги до UI (Frontend)

### 1. Авторизаційний Попап
- Виводиться поверх головної сторінки, якщо кука сесії відсутня.
- Містить дві форми: **Вхід** та **Реєстрація**.

### 2. Форма Реєстрації
- Поля: `login` (текст), `password` (пароль), `confirm_password` (пароль).
- Валідація: `confirm_password` повинен збігатися з `password`, мінімальна довжина пароля.

### 3. Форма Входу
- Поля: `login` (текст), `password` (пароль).
- Кнопки: "Увійти", "Зареєструватися" (перемикає на форму реєстрації).

### 4. Поведінка після дії
- Після успішної реєстрації/входу: Попап закривається, сторінка оновлюється, кука встановлюється.
- Використання **CSS Modules** для стилізації в стилі "Dark Fantasy".

## Технічні деталі
- **Хешування**: Використовувати стандартну бібліотеку для хешування паролів у Node.js.
- **Cookie**: Встановлювати як `HttpOnly` та `SameSite=Lax` для безпеки.
- **SQLite**: Використовувати драйвер `sqlite3` або `better-sqlite3`.
