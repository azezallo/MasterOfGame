# Специфікація фічі: Вибір сесії (Session Selection)

## Огляд
Ця фіча дозволяє гравцеві переглянути список усіх доступних ігрових сесій та вибрати одну з них для продовження гри. Після вибору сесії додаток переходить у стан «Ігрового вікна» (на даному етапі — заглушка).

## Роль гравця
- **Авторизований гравець**: Бачить таблицю доступних сесій на головній сторінці після успішного входу.

## Вимоги до даних (Database Schema - `saves/users.db` / Session Metadata)

Для кожної сесії необхідно зберігати розширені метадані. 
Об'єкт **SessionMetadata** повинен включати:
- `session_id`: Унікальний ідентифікатор (Primary Key).
- `game_name`: Назва конкретної гри/світу (наприклад, "Dark Forest", "Iron Fortress").
- `character_name`: Ім'я героя в цій сесії.
- `created_at`: Unix timestamp моменту створення сесії.
- `last_played_at`: Unix timestamp моменту останнього запису в базу даних цієї сесії.

## Вимоги до API (Backend)

### 1. Отримання списку сесій (`GET /sessions`)
- **Механізм**: Витягувати `session_id` з куки.
- **Дії**:
    - Перевірити валідність сесії.
    - Зібрати всі доступні `.db` файли для поточного гравця.
    - Для кожного файлу отримати або створити `SessionMetadata`.
- **Відповідь**: Список об'єктів сесій:
    ```json
    [
      {
        "session_id": "uuid-123",
        "game_name": "Dark Forest",
        "character_name": "Eldrich",
        "created_at": 1700000000,
        "last_played_at": 1700050000
      }
    ]
    ```

### 2. Перевірка активності сесії (Internal)
- Кожен запит до конкретної ігрової сесії повинен оновлювати поле `last_played_at` у метаданих цієї сесії.

## Вимоги до UI (Frontend)

### 1. Екран вибору сесії
- Відображається як головна сторінка після авторизації.
- Містить таблицю з наступними колонками:
    - **Назва** (Game Name)
    - **Створено** (Created At — відформатований час)
    - **Остання гра** (Last Played — відформатований час)
    - **Ім'я героя** (Character Name)
- Стилізація: Таблиця має відповідати стиліці "Dark Fantasy" (використання CSS Modules, кольори золота, заліза та пергаменту).

### 2. Взаємодія
- Кожен рядок таблиці є клікабельним.
- При кліку на рядок додаток:
    1. Оновлює URL, додаючи параметр `session_id` (наприклад, `?session_id=...`).
    2. Перемикає стан додатка на "Game View".
    3. На даному етапі відображає заглушку "Game View Loading...".
- При завантаженні сторінки додаток повинен перевіряти наявність `session_id` в URL та автоматично перемикатися в режим гри, якщо він присутній.

## Технічні деталі
- **Дата/Час**: Використовувати стандартні методи форматування дати для відображення в UI.
- **Адаптивність**: Таблиця повинна коректно відображатися на великих екранах. На планшетах та мобільних пристроях інтерфейс повинен автоматично перемикатися з табличного вигляду на картковий (карти мають містити всю необхідну інформацію: назву, дату створення, останню гру та ім'я героя).
- **Використання компонентів**: Використовувати існуючі компоненти `Table`, `Button`, `Input` з дизайн-системи.
