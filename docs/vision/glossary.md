# Словник термінів проєкту (Glossary)

Цей документ містить ключові терміни та концепти, які використовуються в архітектурі та документації гри. Усі нові агенти та розробники повинні ознайомитися з цим словником для правильного розуміння філософії проєкту.

## Архітектурні та Рольові терміни

- **ШІ-Майстер (AI Master / Sovereign AI)** 
  Центральна нейромережа гри, яка виконує роль "Dungeon Master" (Майстра Гри). Майстер читає наративні дії гравця, оцінює їхню логіку, фізику світу та контекст, після чого відповідає текстом і **самостійно викликає бекенд-інструменти (API)** для зміни стану гри. Майстер має абсолютну владу над правилами.

- **Наративний інтерфейс (Narrative-First UI)**
  Принцип розробки фронтенду, за яким інтерфейс користувача (UI) є виключно **дзеркалом (read-only)** ігрового стану. У грі відсутні механічні кнопки дій (наприклад, "Атакувати", "Надіти", "Зламати замок"). Гравець взаємодіє зі світом виключно через текстовий чат, описуючи свої дії Майстру.

- **Тули / Інструменти (API Tools / Function Calling)**
  Бекенд-функції (JSON-RPC), які доступні **тільки ШІ-Майстру**. Це технічний міст між наративом ШІ та базою даних гри. Гравець ніколи не викликає тули напряму. Приклади: `equip_item`, `update_reputation`, `move_player`.

- **Вільна Магія (Free-form Magic)**
  Базова фішка гри. Відсутність захардкоджених заклинань. Гравець описує бажаний магічний ефект у чаті, а Майстер оцінює, чи вистачить у гравця Рівня Навичок, Швидкості відновлення мани та Запасу мани (з системи F009) для реалізації цього задуму.


## Документація

- **F-коди (напр., F007, F014)**
  Ідентифікатори ключових фіч (Feature ID) згідно з `roadmap.md`. На них прийнято посилатися в коментарях до коду та специфікаціях для зв'язування різних модулів.
