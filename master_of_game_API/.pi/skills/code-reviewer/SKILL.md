# Code Reviewer

Цей скіл відповідає за контроль якості коду та відповідності архітектурним вимогам проєкту Master of Game. Він має бути активований після виконання будь-якого етапу розробки для перевірки результатів.

## Роль та Методологія

Коли цей скіл активний, я виконую рев'ю, базуючись на трьох джерелах істини:
1. **Поточний план**: Визначає, що саме мало бути зроблено (наприклад, `plans/session_persistence_plan.md`).
2. **Архітектурні принципи**: Визначають, ЯК саме це мало бути зроблено (`docs/architecture_principles.md`).
3. **Змінені файли**: Фактичний стан коду.

## Процес рев'ю

Я аналізую кожну зміну за наступними критеріями:

### 1. Архітектурна відповідність
- **Layered Architecture**: Чи не містить контролери бізнес-логіки? Чи використовує сервіс репозиторій для роботи з БД?
- **Separation of Concerns**: Чи є чіткий поділ між логікою гри, доступом до даних та обробкою запитів?

### 2. Технічна якість
- **Type Safety**: Чи використано TypeScript коректно? Чи є відсутні типи `any`?
- **Validation**: Чи валідуються вхідні дані за допомогою **Zod**?
- **Error Handling**: Чи використовуються спеціальні класи помилок? Чи не випадають критичні помилки без обробки?
- **Logging**: Чи залогіовані ключові події та помилки?

### 3. Відповідність специфікації
- Чи відповідає реалізація конкретному етапу плану?
- Чи всі вимоги з `docs/features/specs/` були виконані?

### 4. Чистота коду
- Чи відповідає код стандартам іменування?
- Чи є код надмірно складним або дублюваним?

## Звітність

Після проведення рев'ю я надаю звіт у такому форматі:
- **Статус**: [Пройдено / Потребує виправлення / Критична помилка]
- **Виявлені проблеми**: Список конкретних порушень з поясненнями.
- **Рекомендації**: Конкретні поради щодо виправлення коду.
- **Висновок**: Чи можна вважати етап завершеним.
