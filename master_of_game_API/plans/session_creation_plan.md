# План розробки бекенд-частини: Створення сесії (Session Creation)

## Огляд
Реалізація функціоналу створення нових ігрових сесій. Бекенд повинен забезпечити генерацію унікальних сесій, створення відповідних файлів баз даних та ініціалізацію метаданих з урахуванням введених користувачем даних.

## Етапи виконання

### Етап 1: Оновлення існуючої інфраструктури
- [ ] Оновити метод `PersistenceService.createSession(playerId)` у `master_of_game_API/src/persistence/persistence_service.ts`, щоб він приймав опціональні параметри `gameName` та `characterName`.
- [ ] Оновити `SessionMetadataService.createMetadata` для коректної обробки цих параметрів під час створення нової сесії.
- [ ] Переконатися, що `SessionMetadataSchema` коректно валідує вхідні дані.

### Етап 2: Реалізація API ендпоінтів
- [ ] Створити контролер та маршрут `POST /sessions`:
    - Витягувати дані гравця з авторизаційних даних.
    - Викликати оновлений метод створення сесії.
    - Повернути відповідь із даними новоствореної сесії.
- [ ] Інтегрувати валідацію вхідних даних за допомогою **Zod**.

### Етап 3: Тестування та верифікація
- [ ] Перевірити створення файлу БД у правильній директорії гравця.
- [ ] Перевірити коректність запису метаданих (назви мають збігатися з введеними).
- [ ] Виконати тестування сценаріїв: створення успішної сесії, створення з порожніми полями, створення для неавторизованого користувача.

## Критерії прийняття (Acceptance Criteria)
1. Бекенд створює новий `.db` файл у папці гравця при кожному успішному запиті `POST /sessions`.
2. Кожна нова сесія отримує унікальний `session_id`.
3. Метадані сесії (назва гри, ім'я героя, дати) коректно зберігаються і повертаються в відповідь.
4. Авторизація працює коректно: лише авторизовані гравці можуть створювати сесії.
5. Відповідь відповідає специфікації `docs/features/specs/session_creation.md`.
