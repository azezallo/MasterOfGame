# Специфікація: Створення сесії (Session Creation)

## Огляд
Реалізація інтерфейсу для створення нової ігрової сесії. Користувач повинен мати можливість ввести назву гри та ім'я героя, після чого система створить нову сесію та автоматично перемкне його на неї.

## Вимоги до функціональності

### 1. Введення даних та валідація
- **Поля форми**:
    - `gameName`: Текстове поле для назви гри.
    - `characterName`: Текстове поле для імені героя.
- **Валідація клієнтської частини (Zod)**:
    - Обидва поля повинні мати довжину від 1 до 255 символів.
    - Дозволяються будь-які символи.
    - Валідація повинна проводитися перед відправкою запиту на бекенд.

### 2. Інтерфейс користувача (UI/UX)
- **Модальне вікно**: Форма створення має відкриватися у модальному вікні (Popup).
- **Стилістика**: Використання CSS Modules у стилі "Dark Fantasy" (пергамент, залізо, вогонь, золото).
- **Адаптивність**: На мобільних пристроях модальне вікно повинно розтягуватися на весь екран.
- **Стани завантаження**: Під час виконання запиту на створення сесії модальне вікно повинно повністю перекриватися спіннером (Spinner) для відображення активного процесу.
- **Обробка помилок**: Використання схеми обробки помилок, аналогічної формі авторизації (відображення повідомлень про помилки на рівні полів або загальної області форми).

### 3. Навігація та стан
- **Автоматичне перемикання**: Після успішного створення сесії користувач має миттєво переводитися на створену сесію.
- **Механізм переходу**: Перехід здійснюється шляхом оновлення параметрів запиту в URL (наприклад, `?session_id=...`), відповідно до реалізації в модулі вибору сесій.

## Архітектура (Feature-Based)
- **Path**: `src/features/session_creation/`
- **Presentation Layer**: Компоненти форми, модального вікна та обробники подій.
- **Logic Layer**: Кастомні хуки для керування станом форми, валідацією та відправкою запитів.
- **API Layer**: Використання `src/api/contracts/sessions.ts` для визначення типів та `src/api/sessions.ts` для виконання запитів.
- **Types**: Використання Zod-схем для валідації даних форми.

## Технічні деталі
- **CSS Modules**: Використовувати для ізоляції стилів.
- **React Hook Form**: Рекомендовано для керування станом форми.
- **Zod**: Для валідації даних.
