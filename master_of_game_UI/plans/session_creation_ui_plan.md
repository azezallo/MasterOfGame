# План розробки фронтенд-частини: Створення сесії (Session Creation)

## Огляд
Реалізація інтерфейсу для створення нової ігрової сесії. Користувач повинен мати можливість ввести назву гри та ім'я героя, після чого система створит нову сесію та автоматично перемкне його на неї.

## Етапи виконання

### Етап 1: Підготовка компонентів та стилів
- [x] Використати існуючі компоненти `Input`, `Button` та модальні вікна з папки `src/components/ui/`.
- [x] Створити специфічні стилі для форми створення сесії (використання CSS Modules у стилі "Dark Fantasy").

### Етап 2: Реалізація модального вікна створення (Popup)
- [x] Створити компонент форми створення сесії у модальному вікні.
- [x] Додати кнопку "Створити нову гру", розташовану над таблицею вибору сесій.
- [x] Реалізувати поля: `gameName` (текст), `characterName` (текст).
- [x] Забезпечити модульну структуру форми для легкого додавання нових полів у майбутньому без суттєвої переробки основної логіки запиту.

### Етап 3: Логіка даних та Навігація
- [x] Створити сервіс для створення сесій (`POST /sessions`).
- [x] Реалізувати логіку відправки даних:
    - Збирати дані з форми.
    - Надсилати запит на бекенд.
    - При успішному запиту отримувати `session_id` та дані новоствореної сесії.
- [x] РеалізТИ увати автоматичне перемикання стану:
    - Після успішного створення перемкнути користувача на створену сесію.

### Етап 4: Фіналізація та Тестування
- [x] Перевірити коректне відображення даних у відповіді від бекенду.
- [x] Перевірити адаптивність форми (модальне вікно має коректно відображатися на планшетах та мобільних пристроях).
- [x] Виконати візуальний аудит відповідності дизайну "Dark Fantasy".

## Критерії прийняття (Acceptance Criteria)
1. Кнопка створення сесії знаходиться над таблицею вибору сесій.
2. Форма створення відкривається саме як модальне вікно (Popup).
3. Форма має модульну структуру для розширень.
4. Після створення сесії користувач автоматично переводиться у нову сесію.
5. Використовуються існуючі компоненти дизайн-системи.
