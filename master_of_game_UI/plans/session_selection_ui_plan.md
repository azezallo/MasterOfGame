# План розробки фронтенд-частини: Вибір сесії (Session Selection)

## Огляд
Реалізація головного екрана вибору ігрової сесії після авторизації. Інтерфейс повинен дозволяти гравцеві переглянути список своїх збережених ігор та вибрати одну з них, зберігаючи стан вибору через URL для забезпечення відношення сторінки.

## Етапи виконання

### Етап 1: Підготовка компонентів та стилів
- [ ] Ідентифікувати та підготувати існуючі компоненти з `src/components/ui/` (кнопки, текстові блоки, контейнери).
- [ ] Створити специфічні стилі для таблиці та карток у стилі "Dark Fantasy" (використання CSS Modules).
- [ ] Визначити кольорову схему для статусів (наприклад, "Останнє оновлення" може мати золотистий або срібний акцент).

### Етап 2: Реалізація компонентів відображення списку
- [ ] Створити компонент `SessionTable` для десктопних пристроїв (колонки: Назва, Створено, Остання гра, Ім'я героя).
- [ ] Створити компонент `SessionCard` для планшетів та мобільних пристроїв (вертикальна композиція даних).
- [ ] Реалізувати логіку адаптивної зміни вигляду: автоматичне перемикання між `SessionTable` та `SessionCard` залежно від ширини екрана.
- [ ] Інтегрувати компонент "Заглушка ігрового вікна" (Game View Placeholder).

### Етап 3: Логіка даних та Навігація
- [ ] Створити сервіс для отримання даних сесій (`GET /sessions`).
- [ ] Реалізувати інтеграцію з URL:
    - Функція оновлення параметрів запиту (`?session_id=...`).
    - Функція зчитування `session_id` при ініціалізації сторінки.
- [ ] Створити глобальний стан або контекст для зберігання активного `session_id`.
- [ ] Реалізувати перемикач станів: "Вибір сесії" <-> "Ігрове вікно".

### Етап 4: Фіналізація та Тестування
- [ ] Перевірити коректність відображення дат (форматування `created_at` та `last_played_at`).
- [ ] Виконати тестування адаптивності на різних розмірах екранів.
- [ ] Виконати візуальний аудит відповідності дизайну "Dark Fantasy".

## Критерії прийняття (Acceptance Criteria)
1. Спис сесій коректно відображається після входу в систему.
2. Використовуються існуючі компоненти дизайн-системи.
3. Таблиця коректно перетворюється на картки на планшетах та мобільних пристроях.
4. Вибір сесії зберігається в URL параметрах.
5. Перемикання на ігрове вікно відбувається миттєво після кліку на будь-який рядок/картку.
