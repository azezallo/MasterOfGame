 # План розробки специфікації: Магія (F015)

Цей документ є покроковим планом для пропрацювання архітектури та написання специфікації фічі **F015 (Інструменти Агента: Магія)** на основі `magic_bible.md`. Головна мета — зробити систему магії стабільною (відстеження через бекенд), але зберегти гнучкість і не перевантажити інтерфейс.

## Етапи розробки специфікації

- `[ ]` **Етап 1: Концепція Мани та Регенерації (Mana & Environment)**
  - Як зберігати рівень мани гравця (зв'язок з F009).
  - Як визначати магічний фон локації (Зони з високою маною, Нульові зони) і як це впливає на автоматичну регенерацію (зв'язок з F006/F008).
  - Логіка харчування/відпочинку для відновлення мани в нульових зонах.

- `[x]` **Етап 2: Здібності та Навички (Magic Affinities vs Spells)**
  - Схема збереження магічних знань (органічні семантичні теги та вільна магія).

- `[x]` **Етап 3: Механіка Касту, Вартість та Баланс (Casting, Cost & Balance)**
  - Алгоритм для ШІ-Майстра: як він повинен визначати вартість заклинання (від сірника до знищення міста).
  - Баланс вільної магії: як запобігти "читерству" (наприклад, вбивству боса однією бульбашкою повітря в мозку), спираючись на опір або складність.
  - Механіка "Нестабільності": як Майстер вирішує, чи втратив гравець концентрацію, і які наслідки це має.

- `[x]` **Етап 4: Магічні предмети та Фокуси (Magic Items Integration)**
  - Зв'язок з F014. Як зберігати предмети концентрації (палички, жезли) та накопичувачі мани (кристали, концентрована мана).
  - Роль цих предметів при касті (наприклад, зменшення ризику нестабільності).

- `[x]` **Етап 5: Магія Інформації (Information Gathering Rules)**
  - Жорсткі правила (промпти) для Майстра щодо заклинань пошуку/передбачення. Магія дає лише "сирі" сенсорні дані, а не готові висновки чи істини.

- `[x]` **Етап 6: Інструменти API (Master Tools)**
  - Проєктування конкретних тулів для Майстра (або розширення існуючих). Наприклад: чи потрібен окремий тул `cast_spell`, чи Майстер просто використовує `update_player_state` для списання мани після свого наративного рішення.

- `[x]` **Етап 7: Відображення на UI (Frontend Representation)**
  - Як показати ману гравцю, щоб не перевантажити інтерфейс (наприклад, мінімалістична смужка під здоров'ям).
  - Відображення магічного фону локації (можливо, невеликий значок біля погоди).
