# План реалізації F017: Семантична пам'ять (Vector DB)

Цей документ описує покроковий план розробки специфікації Семантичної пам'яті (RAG) для локальних LLM. Головна мета — збереження довгострокової історії гри з можливістю швидкого пошуку без перевантаження VRAM та контекстного вікна.

- `[x]` **Етап 1: Архітектура та Технології (SQLite + Embeddings)**
  - Використання наявної БД через `better-sqlite3` із векторним розширенням (наприклад, `sqlite-vec` або `sqlite-vss`), щоб не плодити зайві сутності.
  - Генерація ембеддингів на рівні Node.js (через `fastembed` або `Transformers.js`) на CPU.

- `[x]` **Етап 2: Схема Даних та Метадані**
  - Структура таблиці векторної історії.
  - Набір метаданих (номер ходу, локація, залучені NPC) для фільтрації та гібридного пошуку.

- `[x]` **Етап 3: Агентний інструмент пошуку (`search_memory`)**
  - Специфікація цілеспрямованого інструменту для Майстра/Сабагентів.
  - Ліміти на об'єм повернених даних (запобігання переповненню промпту).

- `[x]` **Етап 4: Управління та Конфлікти Пам'яті**
  - Як діяти, коли стара пам'ять суперечить новим фактам.

---

**Поточний статус:** Усі етапи завершені. Специфікація F017 повністю готова!
