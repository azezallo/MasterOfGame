# План реалізації F017: Семантична пам'ять (Vector DB)

Цей документ описує покроковий план розробки специфікації Семантичної пам'яті (RAG) для локальних LLM. Головна мета — збереження довгострокової історії гри з можливістю швидкого пошуку без перевантаження VRAM та контекстного вікна.

## Етапи реалізації специфікації (`agent_tools_semantic_memory.md`):

- `[ ]` **Етап 1: Архітектура та Технології**
  - Вибір векторного сховища (наприклад, Chroma, Qdrant або SQLite з pgvector/vss).
  - Використання `fastembed` (або іншого легкого рішення) для генерації ембеддингів виключно на CPU, щоб зберегти VRAM для основної моделі.

- `[ ]` **Етап 2: Схема Даних та Метадані**
  - Що саме ми зберігаємо (стиснені логічні факти, вводи гравця, результати інструментів).
  - Які метадані потрібні для покращення пошуку (номер ходу, локація, імена NPC, теги), щоб дозволити гібридний пошук (наприклад, "знайди згадки про Річарда ТІЛЬКИ в локації Ліс").

- `[ ]` **Етап 3: API та Інтеграція в Агентний Цикл**
  - Специфікація автоматичного RAG-запиту (Крок 2 Агентного циклу).
  - Специфікація інструменту `search_memory(query, filters)` для Сабагентів, включаючи жорсткі ліміти на об'єм повернених даних.

- `[ ]` **Етап 4: Управління та Конфлікти Пам'яті**
  - Як діяти, коли стара пам'ять суперечить новим фактам (наприклад, пам'ять каже, що гоблін живий, але в активному контексті він щойно помер).
  - Утилізація (видалення/перезапис) застарілих або невалідних спогадів (чи ми зберігаємо історію як незмінний літопис?).
