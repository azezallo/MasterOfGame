# План реалізації F018: Універсальний RAG-конвеєр

Цей документ описує покроковий план створення специфікації для Універсального RAG (Retrieval-Augmented Generation). Мета фічі — автоматично підтягувати потрібний контекст з різних джерел (пам'ять, лор, правила гри) перед кожним ходом Майстра.

## Етапи реалізації специфікації (`agent_tools_universal_rag.md`):

- `[x]` **Етап 1: Векторизація Динамічних Сутностей (Entity RAG)**
  - Додавання можливості семантичного пошуку для бази `locations`, `organizations` та `npcs`.
  - Правила синхронізації: коли Майстер створює або оновлює опис NPC/локації на льоту, його вектор теж оновлюється.

- `[x]` **Етап 2: Логіка Авто-підтягування (Auto-Prefetch)**
  - Як бекенд аналізує запит гравця і паралельно шукає в `semantic_history` та серед Сутностей.
  - Який формат підтягується: для Локацій це `NAVIGATION_MODE` (короткий опис), для Організацій — деталі, для NPC — контекст у режимі `DIALOG`.
  - *Важливо:* Предмети (артефакти) виключаються з RAG через ризик шуму ("меч" знайде всі мечі гри). Їх Майстер шукає тільки цілеспрямовано.

- `[x]` **Етап 3: Ін'єкція Статичних Правил (Rules Engine)**
  - Два формати системних правил (Магія та Базові правила): Спрощена версія (завжди в промпті) та Повна версія.
  - Механізм визначення релевантності: як бекенд вирішує, коли саме вставити Повну версію правил (через простий семантичний метчинг або класифікатор).

- `[x]` **Етап 4: Формування Системного Промпту (Prompt Assembly)**
  - Як ці автоматично знайдені дані (Історія + NPC/Локації + Правила) структурувати в промпті, щоб Майстер їх чітко розрізняв і не плутав з поточними подіями.
