# План деталізації специфікації системи Предметів та Об'єктів світу (`agent_tools_item.md`)

Цей план описує послідовні етапи проробки специфікації для нової фічі **F014: Інструменти Агента: Предмети та Об'єкти світу**. 
Мета — створити єдиний стандарт бази даних предметів (шаблони, магічні/фізичні властивості, ключі, контейнери) та інструменти ШІ-Майстра для їх генерації, читання й розміщення у світі.

---

## Етапи деталізації

### Етап 1: Класифікація та Властивості предметів (Item Types & Core Properties)
*Ціль: Сформувати базову структуру та атрибути предметів.*
- [x] **Типологія предметів**: Визначення 9 категорій (`weapon`, `armor`, `jewelry`, `consumable`, `key`, `container`, `document`, `artifact`, `misc`).
- [x] **Фізичні та економічні атрибути**: Вага, міцність/стан (`intact`, `worn`, `damaged`, `broken`), базова вартість.
- [x] **Магічні властивості та Пізнання (Identification)**: Подвійна система знань (непізнані предметі для гравця та справжні властивості для Майстра), магічні заряди та ефекти.

### Етап 2: Спеціальні механіки: Ключі, Контейнери та Документи (Keys, Containers & Documents)
*Ціль: Зв'язати предмети з іншими системами мапи та сюжету.*
- [x] **Система ключів (`key_id`)**: Інтеграція предметів-ключів із замками проходів (`transitions.lock_details.key_id`) та скринь.
- [x] **Контейнери та Скрині**: Репрезентація предметів, які містять вкладений список інших предметів (`contained_item_ids`), мають власний замок та приховані пастки.
- [x] **Книги, листи та записи**: Спосіб зберігання текстового контенту предметів (історія, чутки, магічні заклинання), який Майстер наративно зачитує при вивченні.

### Етап 3: Шаблони та Динамічна генерація (Templates & Procedural Generation)
*Ціль: Уникнути дублювання даних у БД та дозволити генерацію луту "на льоту".*
- [x] **Спадкування шаблонів (Template Inheritance)**: Модель, де конкретний екземпляр предмета у світі посилається на базовий шаблон (наприклад: `tpl_iron_sword`), маючи власні унікальні модифікатори (іржа, гравіювання, чари).
- [x] **Процедурна генерація луту**: Правила створення нових предметів Майстром під час обшуку трупів, скринь чи кімнат.

### Етап 4: Інструменти Майстра та Програмний Інтерфейс (Function Calling API)
*Ціль: Визначити повний технічний контракт тулів для ШІ-Майстра.*
- [x] **Специфікація тулів**: Розробка 7 інструментів (`get_item_context`, `search_items`, `create_item`, `update_item_properties`, `reveal_item_secret`, `unlock_container`, `read_document`) з підтримкою глибокої модифікації предметів (накладення магії на звичайну зброю, перетворення на ключ).

### Етап 5: Відображення на UI (Frontend Representation — Player UI Only)
*Ціль: Визначити принципи відображення предметів на клієнті.*
- [x] **Ізоляція та приховування даних**: Відсікання прихованих магічних властивостей, пасток у скринях та справжньої вартості непізнаних предметів від DevTools.
- [x] **Підказки (Tooltips) та Досьє предмета**: Візуальне відображення характеристик предмета при кліку в панелі оточення чи інвентарі (кнопки з кольоровою індикацією зносу `intact/worn/damaged/broken` у лівому сайдбарі, згруповані за категоріями, та модальне вікно досьє при натисканні).
