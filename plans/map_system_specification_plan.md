# План деталізації специфікації системи Мапи та Локацій (`agent_tools_map.md`)

Цей план описує покроковий процес архітектурного пропрацювання та деталізації модуля географії, навігації та управління локаціями перед його фіналізацією та реалізацією у коді.

---

## Етапи деталізації

### Етап 1: Топологія та Структура даних (Topology & Data Schema)
*Ціль: Визначити гібридну модель зберігання простору (Матриця для БД/UI → Графова проекція для ШІ).*
- [x] **Розріджена Ієрархічна Матриця та Дворежимні інтер'єри**: Визначення вкладених сіток координат (Регіон → Поселення/Зона → Будівля/Підземелля), безперервності водних шляхів/доріг та розділення інтер'єрів на 2 режими: 1) Прості POI (атомарний тайл для таверн/крамниць), 2) Складні багаторівневі підземелля (3D-Матриця `x, y, z` із "Туманом війни" для UI та точними вертикальними зв'язками для ШІ-Майстра, який наративно описує спуск чи падіння у провалля і самостійно викликає тул `move_player`).
- [x] **Графова проекція та Схема переходу (Exits / Custom Transitions)**: Алгоритм перетворення сусідніх клітинок на спрямований граф виходів для ШІ, структура ребер (двері, сходи, нерегулярні таємні тунелі, час переміщення).
- [x] **Схема локації (`location_data_schema.md`)**: Створення детальної JSON-схеми для зберігання об'єкта тайла/локації в базі даних SQLite.

### Етап 2: Ініціалізація та Генерація рівнів (Level Initialization & Generation)
*Ціль: Описати специфіку побудови та управління локаціями на різних рівнях масштабу.*
- [x] **Ініціалізація регіонального рівня (World/Region Level)**: Попередня генерація глобальної мапи на етапі створення гри, задання кліматичних зон, фракційного контролю, генерація рік/доріг та насиченості природи маною (`mana_density`).
- [x] **Ініціалізація поселень та відкритих зон (Settlement/Zone Level)**: Збереження міст як генераційних каркасів (`settlement_blueprint`) та псевдорандомна генерація вулиць/будівель "на льоту" на основі біому, сусідів та параметрів каркасу при відвідуванні.
- [x] **Ініціалізація закритих локацій та підземель (Indoor/Dungeon Level)**: Генерація за явним запитом ШІ-Майстра під потреби сюжету/квесту для попереднього розміщення об'єктів, можливості видачі чуток та карт гравцеві задовго до спуску.

### Етап 3: Динаміка, Секрети та Стан світу (Dynamic State & Secrets)
*Ціль: Визначити правила зміни оточення під час гри.*
- [x] **Життєвий цикл та управління станом локації (`state_modifications`)**: Збереження руйнувань, написів, покинутих предметів чи трупів з ігровим таймкодом. Наративне обчислення змін та очищення сміття (Garbage Collection) ШІ-Майстром при повторному візиті з урахуванням біому і минулого часу.
- [x] **Схема "Відкритих секретів" локації**: Реалізація прихованих проходив, схованок і пасток через надійний ключ `secret_id` та суворо наративний принцип розкриття (без UI-плашок, з органічним слідом у `public_description`).
- [x] **Глобальний стан світу та координація**: Ієрархічне розповсюдження `state_modifications` з рівня регіону на поселення/кімнати. Використання тула вимірювання відстаней `calculate_distance` для оцінки Майстром сили впливу глобальних подій (війни, зими) на конкретні міста.

### Етап 4: Контекст та Інтеграція з Майстром (AI Context Optimization)
*Ціль: Забезпечити ефективну передачу географічних даних у промпт без токенного вибуху.*
- [x] **Режими витягування даних**: Деталізація трьох токен-оптимізованих режимів (`NAVIGATION_MODE`, `DETAILED_MODE`, `REGIONAL_MODE`) з читкою фільтрацією прихованих даних.
- [x] **Зв'язок із сутностями та Динамічна присутність**: Відмова від статичної прив'язки 24/7 у полі `associated_npc_ids`. Бекенд динамічно розраховує фактичну присутність NPC за їхнім розкладом та ігровим часом, з можливістю Майстерського перехоплення (Narrative Override) при подіях.

### Етап 5: Інструменти Майстра та Програмний Інтерфейс (Function Calling API)
*Ціль: Визначити повний технічний контракт тулів для ШІ-Майстра.*
- [x] **Програмний інтерфейс тулів**: Специфікація 8 функцій для читання (`get_location_context`), пошуку (`search_locations`), розрахунку відстаней (`calculate_distance`), переміщення (`move_player`), зміни стану середовища й переходів (`update_location_state`, `update_transition_status`), розкриття секретів (`reveal_location_secret`) та динамічної генерації ("на льоту") (`create_location`).

### Етап 6: Відображення на UI (Frontend Representation — Player UI Only)
*Ціль: Сформувати конкретні вимоги до фронтенд-компонентів для гравця (інтерфейс людини-Майстра відсутній, оскільки Майстер є автономним ШІ).*
- [x] **Інтерфейс Гравця (Player UI Layout & Interaction)**: Визначення чистого наративного підходу (без кнопок автодії, усі переходи через текстовий чат). Розробка модального вікна Інтерактивної Мапи з підтримкою масштабування, пошуку та ретроспективного огляду старих місць із суворою фільтрацією живих сутностей (NPC/предметів) для віддалених точок.
